Schema Domains¶

The usdAECO suite provides schema domains for describing the built environment on OpenUSD. Each domain is a separate codeless schema library with its own guide. The core domain, usdAeco, carries the semantics every dataset about a built thing shares; every other domain applies to core prims and never changes the core's structure.

  • Built Environment (usdAeco) Identity, the five-type spatial structure, classification against external dictionaries, systems and zones, ports, catalog types and occurrences, phase, and the mark on derived geometry. The core: no dependencies, no geometry schemas, no dates.
  • Path Drivers (usdAecoAxis) Line and circular-arc path drivers for walls, pipes and beams, with derived guide curves. Section tier.
  • Layered Sections (usdAecoBuildUp) Layered build-ups shared by walls, floors, roofs and ceilings, owned by catalog classes. Section tier.
  • Walls (usdAecoWall) and Pipes (usdAecoPipe) Element-kind drivers: axes, sections, joins, openings, nominal sizes and connected fittings; bodies come from the authoring kernel.
  • Host Sync (usdAecoSync) Edit drivers in an intent layer, let an installed host solve them, publish results and diagnostics separately. Record tier.
  • Cameras, Clash, Programmes, Repeated Floors, Compliance, Exact Bodies Use-case domains that derive findings over the built thing: camera coverage, clash evidence with measured uncertainty, programmes and 4D playback, floor-to-floor drift, requirement checks, and exact BRep bodies with proxy twins.

Guides marked "to follow" link to their repositories until their pages exist.
